# v83 boss and mini-boss inventory

> Research for the region progression (#447, #448, #449), 2026-10-30. Read from the owner's v83 files with `tools/wzimport dump` and throwaway scripts (not committed; mentions of `_scratch/` are those). Facts only (ids, names, levels, HP, spans): tier A unless marked inferred.


Source: the owner's original v83 data files. Generated 2026-10-30 with `tools/wzimport` (`wzimport dump`) and scratch parsers in this folder.
Facts are **tier A** (read straight from the files) unless a cell says "inferred". The method, once:

- Mob stats, boss flag, skills, revive, link: `Mob.wz/<id>.img/info` (`level`, `maxHP`, `exp`, `boss`, `skill/N/{skill,level,action}`, `revive`, `link`).
  Attack types: `Mob.wz/<id>.img/attackN/info/type` (0 area, 1 targeted direct, 2 ball, 3/4 other). Animations: the stance nodes (`move`/`fly`/`stand`/`attackN`/`skillN`/`hit1`/`die1`); "own" = the img has real canvases, "link-only" = `info/link` and no stances.
- Names: `String.wz/Mob.img`. Map names/streets/region: `String.wz/Map.img` (group key shown in brackets, e.g. Victoria Is. = group `victoria`, Ossyria = `ossyria`; `special/instance` is group `etc`).
- Native maps, in priority order: `Map.wz/Map/MapN/*.img/life` entries of type `m` (tag `mobTime Ns` = respawn seconds; `-1` = never auto-respawns, i.e. spawned by a script/event; `life` with mobTime 0 = ordinary spawn), then `String.wz/MonsterBook.img/<id>/map` (tag `MB`). Most field bosses (Mano, Stumpy, Dyle, Faust, King Clang, Zakum, Horntail...) have **no life entry**: the server/script summons them, so only MonsterBook tells where they live. The first map also shows the foothold x-span (`Map.wz .../foothold`, all x1/x2) and the map-info `lvLimit` / `timeLimit` / `partyOnly` when set. `lvLimit` is the map's minimum entry level, nothing else in the files states a boss level requirement.
- Mob skills: `Skill.wz/MobSkill.img/<skill>/level/<lv>` (interval, time, prop, x, hp gate, summon list, area). Skill names are NOT in the files; any name I give for an id that our sim does not handle is the usual community meaning and is marked "inferred".
- Sim support: read from `origin/redesign` (`game/scripts/sim/mob_skill_runner.gd`, `boss_attacks.gd`, `mob_attacks.gd`, `game/data/survivor/balance.json`, `stages.json`). `docs/research/monster-status-effects.md` only covers the player-side Slow/Poison/Freeze statuses and elements, it does not list mob skills.

## What our sim can do (origin/redesign)

- `MobSkillRunner.SUPPORTED` = MobSkill **100** (Attack Up self), **110** (Attack Up area), **112** (PDD up area), **113** (MDD up area), **114** (heal area), **126** (Slow on the player), **129** (Banish), **140** (weapon immunity, timed self status), **200** (summon). Every other id on a boss is skipped silently.
- A boss only casts if its mob id is in `balance.mob_skills.enabled_ids` (today: 2220000, 3220000, 9300003, 6220000, 4090000, 5090000). Adding a boss to the whitelist is a data change (tier C).
- Boss attacks: `attackN` info `type` 0 (area), 1 (targeted direct), 2 (ball) only. Types 3 and 4 are rejected (`mob_attacks.gd`: `type not in [0, 1, 2]`). Boss attacks are gated to a grounded, on-screen boss; flyers (`fly` stance: Crimson Balrog, Pachu family, Phoenix, Freezer, Papulatus) move but the attack code requires "grounded" (inferred from the `boss_attacks.gd` doc comment).
- Status resistance: bosses reject Slow/Poison/Freeze (owner decision recorded in `docs/research/monster-status-effects.md`).
- Currently used bosses (`stages.json`): Mano (Henesys m1, Perion m1), Mushmom (Henesys m2), Blue Mushmom 9400205 (Henesys m3), Stumpy (Ellinia m1, Perion m2), King Slime (Ellinia m2, Kerning m1), Dyle (Ellinia m3, Kerning m3), Iron Hook (Perion m3), Shade (Kerning m2), Zombie Mushmom (Sleepywood m1), Snack Bar (Sleepywood m2), Jr. Balrog (Sleepywood m3).

Column "sim gaps" lists what the sim would skip for that mob today: unsupported skill ids, unsupported attack types, flyer attack gating, link-only. "none" = every listed skill id and attack type is already in the runner (it may still need whitelisting). In the main table 47 of 86 rows say "none".

Class column (my grouping): FIELD = open-map boss (timer or script), AREA = fixed dungeon/arena boss, PQ = party-quest boss, SCRIPT = scripted/event-instance chain, SPECIAL = quest/odd-region boss, UNPLACED = boss-flagged and complete in Mob.wz but never placed in Map.wz/MonsterBook of these files.

Counts: 1564 Mob.wz imgs; 461 have `boss=1` (most are event copies, phase bodies and summoner stubs, see Excluded); the main table has 86 rows.

## Caveats

- `boss=1` is unreliable: King Slime, Iron Hook, Chief Gray, Hogul, D. Roy, Homunscullo and every Horntail "whole body" shell have no flag but are bosses/minibosses; many `boss=1` mobs are event stubs.
- HP/EXP are the file values. Survivor stage `hp_mult` rescales them; use the table as canonical input only.
- Native map for most script-summoned bosses comes from MonsterBook; where both life and MB exist, life is listed first.
- A MonsterBook map list can contain the boss's whole region (e.g. Sleepywood maps) even though the boss only spawns at one point.
